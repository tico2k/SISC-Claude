# 선택 연동 가이드 (Microsoft Entra ID / SIEM)

SICS는 **외부 연동 없이 설치하고 바로 사용할 수 있습니다** (자체 계정 로그인, SMTP 메일, 수동 케이스 등록).
Entra ID와 Sentinel 같은 SIEM 연동은 조직 상황에 맞춰 **설치 후 관리자 화면에서** 설정합니다.

| 연동 | 설정 위치 | 저장 위치 | 반영 시점 |
|---|---|---|---|
| Microsoft Entra ID (SSO·사용자 동기화·Outlook 메일) | `외부 연동 설정` (시스템관리자) | DB `integration_setting` (시크릿 암호화) | 저장 즉시 (재시작·재빌드 불필요) |
| SIEM (Microsoft Sentinel 등) | `SIEM 연동` (보안관리자·시스템관리자) | DB `siem_configuration` (시크릿 암호화) | 저장 즉시 (수집 스케줄 자동 등록) |
| Microsoft Teams 채널 알림 | `외부 연동 설정` (시스템관리자) | DB `integration_setting` (웹훅 URL 암호화) | 저장 즉시 |

> 연동 정보(테넌트·클라이언트 ID, 시크릿, 워크스페이스 ID)는 `.env`나 프론트엔드 빌드 변수(`VITE_*`)에 넣지 않습니다.
> 시크릿 암호화에는 `.env`의 `ENCRYPTION_KEY`가 필요합니다.

## 1. Microsoft Entra ID

### 1.1 어떤 기능을 쓸지 먼저 정하기

| 기능 | 필요한 것 |
|---|---|
| SSO 로그인 | 앱 등록 + 테넌트 ID + 클라이언트 ID (시크릿 불필요) |
| 사용자 동기화 (`사용자 관리 > Entra ID 동기화`) | 위 항목 + 클라이언트 시크릿 + Graph `User.Read.All` 애플리케이션 권한 |
| Outlook 메일 발송 | 위 항목 + 클라이언트 시크릿 + Graph `Mail.Send` 애플리케이션 권한 + 발송 사서함 + `.env`의 `MAIL_SENDER_TYPE=OUTLOOK` |

연동을 설정하지 않으면 로그인 화면의 SSO 버튼, 사용자 동기화 버튼은 표시되지 않고, Outlook 메일은 발송되지 않습니다(경고 로그).

### 1.2 Azure Portal에서 앱 등록

1. Azure Portal → **Microsoft Entra ID** → **앱 등록** → **새 등록**
2. 지원되는 계정 유형: **이 조직 디렉터리의 계정만(단일 테넌트)**
3. 리디렉션 URI: 플랫폼 **SPA**, 값은 `https://<SICS 접속 주소>/auth-callback`
   - 정확한 값은 SICS `외부 연동 설정` 화면에 표시됩니다
4. 등록 후 **개요**에서 **디렉터리(테넌트) ID**, **애플리케이션(클라이언트) ID**를 확인합니다

사용자 동기화·Outlook 메일을 쓸 경우에만:

5. **인증서 및 암호** → **새 클라이언트 암호** 생성 후 값을 복사 (생성 직후에만 확인 가능)
6. **API 권한** → **Microsoft Graph** → **애플리케이션 권한**에서 필요한 권한 추가
   - 사용자 동기화: `User.Read.All`
   - 메일 발송: `Mail.Send`
7. **[조직]에 대해 관리자 동의 부여** 클릭 → 상태가 **부여됨**인지 확인

> 메일 발송은 백그라운드 작업에서 사용자 로그인 없이 실행되므로 '위임된 권한'이 아니라 **'애플리케이션 권한'** 이어야 합니다.

### 1.3 SICS에서 설정

1. 시스템관리자로 로그인 → 좌측 메뉴 **외부 연동 설정**
2. 테넌트 ID, 클라이언트 ID 입력 (GUID 형식) → 필요하면 클라이언트 시크릿, 발송 사서함 입력
3. **연동 사용** 체크 후 **저장**
4. **연결 테스트**로 앱 인증(시크릿) 확인 — SSO만 쓰는 경우 시크릿 없이 저장해도 됩니다
5. Outlook 메일을 쓸 경우 `환경 변수 관리`에서 `MAIL_SENDER_TYPE`을 `OUTLOOK`으로 변경

기본 인증 방식을 SSO로 바꾸려면 `.env`의 `DEFAULT_AUTH_METHOD=ENTRA` (또는 `ALLOW_LOCAL_LOGIN=false`)로 설정합니다.
이 경우에도 시스템관리자·보안관리자는 자체 계정으로 로그인할 수 있습니다. Entra 연동이 꺼져 있으면 `ENTRA` 설정은 무시되고 자체 로그인으로 동작합니다.

### 1.4 동작 방식 (보안)

- 프론트엔드는 `/config`에서 받은 클라이언트·테넌트 ID로 실행 중에 MSAL을 초기화하고, 로그인 결과의 **ID 토큰**을 서버로 보냅니다
- 서버는 ID 토큰의 서명(테넌트 JWKS), 대상(`aud` = 등록한 클라이언트 ID), 발급자·테넌트(`iss`, `tid`), 만료를 검증한 뒤 `preferred_username`(UPN)으로 SICS 사용자를 찾습니다
- SICS에 등록되지 않은 사용자는 로그인할 수 없습니다 (사용자 동기화 또는 수동 등록 필요)
- 연동 설정 변경, 사용자 동기화, SSO 로그인은 시스템 감사로그에 기록됩니다 (ID·시크릿 값은 기록하지 않음)

## 2. SIEM (Microsoft Sentinel)

설치 직후에는 SIEM 연결이 없으며 수집 작업도 실행되지 않습니다.

### 2.1 Azure Portal 준비

1. Sentinel이 연결된 **Log Analytics 작업 영역**의 **작업 영역 ID**를 확인합니다
2. 수집용 앱을 등록하고(Entra 연동 앱과 같은 앱이어도 됨) 클라이언트 시크릿을 생성합니다
3. 작업 영역의 **액세스 제어(IAM)**에서 해당 앱에 **Log Analytics 읽기 권한자** 역할을 부여합니다

### 2.2 SICS에서 설정

1. 보안관리자 또는 시스템관리자로 로그인 → **SIEM 연동** → 연결 추가
2. 유형 `Microsoft Sentinel` 선택 후 테넌트 ID, 클라이언트 ID, 시크릿, 작업 영역 ID 입력
3. 수집 쿼리(KQL) 입력 후 **연결 테스트** → 결과 필드를 보고 **필드 매핑** 지정
4. 수집 주기(cron)와 활성 여부를 정하고 저장하면 스케줄러에 자동 등록됩니다

> 필드 매핑은 SIEM·쿼리마다 다르므로 기본값이 없습니다. 매핑을 지정하지 않으면 수집 작업은 실패로 기록되고 케이스를 만들지 않습니다.

## 3. Microsoft Teams 채널 알림 (보안팀)

보안팀 채널에 다음 알림을 보냅니다: 소명 제출(심의 대기), 소명 기한 초과 요약, SIEM 수집으로 새 케이스 생성.
알림에는 케이스 번호·규칙·건수만 담고 **직원 이름과 소명 내용은 넣지 않습니다.** 직원 개인 알림은 기존처럼 메일로 보냅니다.

### 3.1 Teams에서 웹훅 만들기

1. 보안팀 채널 → `...` → **워크플로** → **"웹후크 요청이 수신되면 채널에 게시"** 템플릿 선택
2. 게시할 팀·채널을 고르고 만들기 → 표시되는 **웹훅 URL** 복사

> 기존 Office 365 커넥터(Incoming Webhook)는 Microsoft가 단계적으로 종료 중이므로 Workflows 웹훅을 사용합니다.
> 메시지는 Adaptive Card 형식(`type: message`, `attachments[].contentType = application/vnd.microsoft.card.adaptive`)으로 보냅니다.
> 조직의 Teams 정책에 따라 템플릿 이름이나 허용 여부가 다를 수 있으니, 연결 테스트로 실제 표시를 확인하세요 (확인 필요).

### 3.2 SICS에서 설정

1. 시스템관리자 → **외부 연동 설정** → **Microsoft Teams 채널 알림**
2. 웹훅 URL 입력(https만 허용) → **알림 사용** 체크 → **저장** → **테스트 메시지**로 확인

URL에는 인증 서명이 들어 있어 암호화해 저장하고 화면에 다시 표시하지 않습니다.
